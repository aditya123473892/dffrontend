FRONTEND ISSUES TO FIX
Project: fantacy-chat-frontend
Date: 2026-08-05

1. Socket URL is using a non-public environment variable
Priority: Critical
File: src/app/(protected-routes)/(fantacy)/chats/[group]/[id]/websocketService.tsx
Issue:
- The socket client uses process.env.SOCKET_URL.
- In Next.js browser code, environment variables must be prefixed with NEXT_PUBLIC_.
- Current .env does not define SOCKET_URL or NEXT_PUBLIC_SOCKET_URL.
Impact:
- Chat sockets may connect to undefined or fail in production.
Fix:
- Add NEXT_PUBLIC_SOCKET_URL to .env.
- Change io(process.env.SOCKET_URL) to io(process.env.NEXT_PUBLIC_SOCKET_URL).

2. API auth token is not applied globally
Priority: Critical
File: src/common/utils/axios-instance.ts
Issue:
- Authorization header setup is commented out.
- Many pages manually read localStorage and manually attach Bearer tokens.
Impact:
- API calls can fail inconsistently.
- Code duplication increases risk of missing auth headers.
Fix:
- Add a request interceptor that reads accessToken on the client and attaches Authorization.
- Remove repeated manual token/header logic from pages where possible.

3. localStorage is used directly during render in many client components
Priority: High
Files:
- src/app/(protected-routes)/admin/chats/[group]/[id]/page.tsx
- src/app/(protected-routes)/(fantacy)/chats/[group]/[id]/page.tsx
- src/app/(protected-routes)/admin/users/page.tsx
- src/app/(protected-routes)/admin/dashboard/page.tsx
- src/app/(protected-routes)/(fantacy)/events/page.tsx
- many other protected pages
Issue:
- localStorage is accessed directly at component top level.
Impact:
- Can cause hydration/runtime errors if a component is rendered before browser APIs are available.
- Makes auth state harder to control.
Fix:
- Read localStorage inside useEffect or through a shared client-only auth hook.
- Prefer a single useAccount/useAuth pattern.

5. Chat page opens both direct and group sockets/history for every chat
Priority: High
Files:
- src/app/(protected-routes)/admin/chats/[group]/[id]/page.tsx
- src/app/(protected-routes)/(fantacy)/chats/[group]/[id]/page.tsx
Issue:
- The page calls getChatHistory and getGroupChatHistory.
- It also connects direct socket and group socket.
- This happens even when the route is only one chat type.
Impact:
- Duplicate messages.
- Extra network/socket load.
- Wrong messages can appear in the wrong conversation.
Fix:
- Derive chat type from route params.
- Only connect one socket mode:
  - direct/user/admin chat -> connectSocket + getChatHistory
  - group chat -> connectGroupSocket + getGroupChatHistory

6. Socket disconnect is too broad
Priority: High
File: src/app/(protected-routes)/(fantacy)/chats/[group]/[id]/websocketService.tsx

- Individual components call disconnectSocket during cleanup.
Impact:

9. Message scroll-bottom detection is fragile
Priority: Medium
Files:
- src/app/(protected-routes)/admin/chats/[group]/[id]/page.tsx
- src/app/(protected-routes)/(fantacy)/chats/[group]/[id]/page.tsx
Issue:
- It checks exact equality:
  container.scrollHeight === container.scrollTop + container.clientHeight
Impact:
- Due to sub-pixel values, browser zoom, or layout changes, read receipts/auto-scroll may fail.
Fix:
- Use a threshold:
  Math.abs(container.scrollHeight - container.scrollTop - container.clientHeight) < 10
